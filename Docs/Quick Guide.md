# Right-Click Menu API — Quick Guide

## Project

Windows 11 in-process shell extension that **replaces** (not extends) the right-click context menu in File Explorer with a custom owner-drawn popup. The consumer writes a `menu.cpp` describing the menu as a tree of `Selection` / `Submenu` / `Separator()` macros; the host DLL hooks `user32!TrackPopupMenuEx` and renders its own per-pixel-alpha layered window in place of the system menu.

| Attribute   | Value                                                          |
|-------------|----------------------------------------------------------------|
| Type        | In-process shell-extension DLL + sample consumer DLL + 2 test exes |
| Runtime     | Windows 11 24H2 x64 (verified on build 26200, DPI-aware host) |
| Language    | C++17 (MSVC v143 / `cl.exe /std:c++17`)                       |
| Build       | `build.bat` (cl.exe direct); `CMakeLists.txt` is partial      |
| Entry point | `DllMain` in `src/main.cpp`                                    |
| Output      | `build/shell_extension.dll`, `build/menu.dll`, `build/test_harness.exe`, `build/hook_test.exe` |
| Libraries   | `user32 gdi32 psapi dwmapi ole32 oleaut32 shell32 shlwapi advapi32 windowscodecs msimg32 gdiplus d2d1 dwrite` |
| Test surface | `test_harness.exe` (no hook) → `hook_test.exe` (hook pipeline) → `register.bat` (live in explorer) |
| Custom font | Exo 2 variable font, loaded at runtime via DirectWrite font set |
| Icons       | 9 PNG icons in `assets/icons/`, generated by `test_scripts/extract_icons.py` |


## Architectural Principles (Do Not Violate)

1. **Host process never crashes because of us.** Every shell boundary (`DllMain`, each detour, `build_menu_for_current_click`, every consumer-lambda dispatch) is SEH-wrapped. Faults degrade to no-menu or fall-back-to-original — never propagate.
2. **Inline hook is the actual interception.** IAT hooking proved unreliable; the 12-byte `mov rax, imm64; jmp rax` patch at `user32!TrackPopupMenuEx`'s function entry is what catches calls. IAT hooks remain installed as defense-in-depth (`hook.cpp`).
3. **Tree built via thread-local pointer.** `_menu_internal::currentMenu` is "where I'm adding to". `Submenu`'s `operator+` does push/pop. This is what makes the nested `{ ... }` macro syntax produce a correct tree.
4. **Three-mode export attribute.** `MENU_API_DECL` at `menu_api.h:32-38` distinguishes static link, dllexport, dllimport. Without it, `menu.dll` can't share state with the host.
5. **One window per menu level, each modal.** `menu_window::show_impl` recurses for cascading; the parent's `WndProc` is on the stack while the child runs. This is why the auto-dismiss-on-sibling and `WM_SETCURSOR` overrides exist.
6. **Consumer never types `[&]` or `std::function`.** The macros hide the lambda syntax. A `;` after each closing `}` is the only C++ tax the consumer pays.
7. **Per-pixel-alpha layered window.** `WS_EX_LAYERED` + `UpdateLayeredWindow(ULW_ALPHA)` with a 32bpp BI_RGB top-down DIB. **No** `DwmSetWindowAttribute` (would draw a rectangular non-client frame). **No** `CS_DROPSHADOW` (draws a hard rectangular outline).
8. **Silhouette + border share GDI+ path geometry.** Both the kBg `FillPath` and the navy 1px `DrawPath` use the same rounded-rect path so AA aligns; otherwise corners look bolder than straight edges.
9. **Text via D2D + DirectWrite into a private WIC bitmap.** GDI+ text on a layered DIB renders chiseled because of premultiplied-alpha quirks. D2D into a private bitmap composited back via source-over avoids that. Variable-font `wght` axis is set per text run (label = 450, shortcut/chevron = 250).

## Error Handling

| Layer                         | Mechanism                                                |
|-------------------------------|----------------------------------------------------------|
| `DllMain` body                | SEH `__try / __except` — init failure leaves DLL inert   |
| `build_menu_for_current_click` | SEH — consumer faults swallowed, partial rootMenu kept  |
| Each TPM detour               | SEH — falls back to original TPM or returns FALSE        |
| Handler dispatch              | SEH — consumer lambda faults swallowed                   |
| IAT/inline patch failure      | Logged via `diag::log`; pipeline continues               |
| Consumer DLL load failure     | Tolerated — host stays alive, no menu shown              |
| WIC/D2D/DirectWrite create failure | Logged; rendering of that element skipped           |

The single rule: **the host process never crashes because of us.**


## Dispatch / Control Flow

```
user right-clicks in File Explorer
   │
   ▼  explorer enumerates HKCR\<asset>\shellex\ContextMenuHandlers,
      finds {7C3F4C5E-...}, CoCreateInstance our CLSID
   ▼
LoadLibrary(shell_extension.dll) — DllMain runs
   ├─ load_consumer_dll()  → resolves menu.dll's RegisterMenu
   ├─ install_iat_hooks()  → IAT patches every module's user32!TPM(Ex)
   │                          AND inline-patches user32!TrackPopupMenuEx
   ├─ install_loadlibrary_hook() → IAT patches kernel32!LoadLibraryExW
   │                                so future modules also get patched
   └─ install_cocreateinstance_hook() → IAT patches ole32!CoCreateInstance
                                          to refuse modern-menu CLSIDs
   │
explorer asks for IContextMenu → RcmContextMenu (adds 0 items)
   │
explorer builds + shows the legacy popup via TrackPopupMenuEx
   │
   ▼  inline hook fires
TrackPopupMenuEx_detour [hook.cpp]
   │
   ├─▶ prime_context(owner, x, y)
   │     └─ populate_shell_context [shell_context.cpp]
   │        └─ IShellWindows → IShellBrowser → IFolderView
   │           → IShellItemArray (selection paths)
   │           → set_paths / set_target / set_modifiers
   │
   ├─▶ build_menu_for_current_click [main.cpp]
   │     └─ reset_menu_state + g_registerMenu()
   │        (consumer's RegisterMenu populates rootMenu via macros)
   │
   ├─▶ menu_window::show(rootMenu, x, y, owner)
   │     └─ paint_layered:
   │        1. memset DIB to 0 (transparent)
   │        2. GDI+ on PARGB: silhouette FillPath (kBg) + highlights
   │           + icon DrawImage + separator DrawLine
   │        3. D2D + DirectWrite on private WIC bitmap → composite back
   │           (Exo 2 variable font, wght axis 450/250)
   │        4. GDI+ DrawPath border (navy 1px, same path geometry as silhouette)
   │        5. UpdateLayeredWindow(ULW_ALPHA)
   │     SetCapture, modal GetMessage loop
   │     hover submenu → recurse show_impl
   │     click → return handlerId
   │
   └─▶ dispatch_handler(handlerId)
        └─ handlerRegistry[id]()  (consumer's lambda fires under SEH)
```


## Setup

### Prerequisites

- Windows 11 24H2 x64 (verified on build 26200)
- Visual Studio 2022 Build Tools with **MSVC v143 C++ toolchain**
- **x64 Native Tools Command Prompt for VS 2022** (must be x64, not generic CMD)

### Build

From `WORKING/`, in the x64 VS Developer Command Prompt:

```
build.bat
```

Sequential build order (matters because `menu.dll` links `build/shell_extension.lib`):

1. `test_harness.exe` (static link, `MENU_API_STATIC`)
2. `shell_extension.dll` (`MENU_API_BUILDING_DLL`, `/LD`, `/DEF:src\shell_extension.def`)

4. `hook_test.exe`

`build.bat` also robocopies `assets/icons/*.png` → `build/assets/icons/` and `Font/Exo2-VariableFont_wght.ttf` → `build/Font/`.

None.

```
build\test_harness.exe        Stage 1: API + window paint, no hook
build\hook_test.exe           Stage 2: hook pipeline, no explorer
register.bat (admin)          Stage 3: live in explorer.exe
```

### Troubleshooting

| Symptom                                    | Cause / Check                                              |
|--------------------------------------------|------------------------------------------------------------|
| `cl.exe not found`                         | Not inside the x64 Native Tools Command Prompt             |
| `LNK1104: cannot open file 'build\shell_extension.dll'` | A `hook_test.exe` or registered explorer is holding the DLL. Kill `hook_test.exe`, or restart explorer if registered |
| `hook_test.exe` runs, returns immediately  | No `TrackPopupMenuEx_detour FIRED` in log = hook never installed |
| Menu doesn't appear in explorer right-click | Modern menu not falling through to legacy. Try Shift+right-click. Check `shell_extension.log` for `FIRED` |
| Menu shows but text is missing/chiseled    | DirectWrite font collection failed — check log for `DWriteCreateFactory` and `DWrite font collection` lines |
| Menu position wrong on hi-DPI              | `g_dpi_scale` calc — confirm `GetDpiForWindow(owner)` returned the right monitor DPI in the log |
| Border looks bolder at corners than edges  | Pen alignment — must be `PenAlignmentCenter` with path inset by half-pen-width and corner radius reduced by same |
| Visible rectangular outline outside the rounded silhouette | `CS_DROPSHADOW` is set on the window class — must be removed |


## Recipes

### Add a new menu entry to the example

1. Edit `examples/menu.cpp`.
2. Inside `RegisterMenu()`, add a `Selection("text", "shortcut", "icon.png") { ... };` or `Submenu("text", "icon.png") { ... };` block. Both shortcut and icon are optional.
3. Trailing `;` after the closing `}` is mandatory.
4. If the icon is new, drop the PNG into `assets/icons/<icon.png>`.
5. Rebuild: `build.bat`.
6. Re-run `build\hook_test.exe`, or restart explorer if registered.

### Add a new icon

1. Drop a 28×28 PNG (transparent background preferred) into `assets/icons/<name>.png`.
2. Reference it from a consumer's `Selection(..., "<name>.png")` or `Submenu(..., "<name>.png")` call.
3. Rebuild — `build.bat` robocopies it into `build/assets/icons/`.

### Re-extract icons from the ChatGPT mockup

1. `python test_scripts/extract_icons.py`
2. Reads `~/Downloads/ChatGPT Image May 13, 2026, 09_01_19 PM.png`, finds 9 colored rounded-square blobs via saturation-mask connected-components, crops + resizes to 28×28 with transparent backgrounds, writes to `assets/icons/`.
3. Rebuild: `build.bat`.

### Swap in a different font

1. Drop the `.ttf` into `Font/<your-font>.ttf`.
2. Update the robocopy line in `build.bat` to copy your file.
3. Update the path string in `ensure_custom_font_loaded()` (`menu_window.cpp`) — also update the `IDWriteFactory5::CreateFontFileReference` argument.
4. Update the family name in the two `CreateTextFormat` calls (one in `make_text_format`, one in the chevron block) — find the family by running `python test_scripts/print_font_names.py` against the new TTF.
5. Rebuild.

### Add a new `ClickTarget` value

1. Add the enumerator to `enum class ClickTarget` at `menu_api.h:46`.
2. If anything in `shell_context.cpp::infer_single_target` should set it, wire that up.
3. No other changes needed — the consumer uses it via `if (target == ClickTarget::NewValue)`.

### Add a new context global

1. Declare it in `menu_api.h` near line 76 with `extern MENU_API_DECL`.
2. Define storage in `context.cpp` near line 16.
3. Reset it in `_menu_internal::reset_context()` in `context.cpp`.
4. Have `shell_context.cpp::populate_shell_context` write to it.
5. Document it in this file's "Data Shapes" section.

### Add a new predicate helper

1. Declare in `menu_api.h` near line 91 with `MENU_API_DECL bool ...`.
2. Implement in `context.cpp`.
3. Consumer uses inline: `if (target == File && my_new_predicate(...))`.

### Wire a new modern-menu CLSID into the refusal list

1. Set `kLogEveryCci = true` at the top of `src/detours_hook.cpp`.
2. Rebuild + restart explorer + reproduce a right-click.
3. Read `build/shell_extension.log` for `CoCreateInstance: clsid=...` lines, identify the modern-menu CLSID.
4. Add it to `kRefusedClsids[]` in `detours_hook.cpp`.
5. Set `kLogEveryCci = false`. Rebuild.

### Add a diagnostic log line

1. `#include "diag.h"` if not already.
2. `diag::log("format string %d %s", x, str);` — works like `printf`.
3. Output goes to `build/shell_extension.log` (mutex-protected, append, timestamped).

### Change the menu colors

1. Edit the color constants near the top of `src/menu_window.cpp` (`kBg`, `kBorder`, `kText`, `kTextMuted`, `kShortcut`, `kSepLine`, `kHighlight`).
2. Rebuild.
3. Highlight should be DIMMER than `kBg`, not brighter — hover dims, not brightens.

### Restart explorer after rebuild (when registered)

1. `taskkill /F /IM hook_test.exe` (if running)
2. `build.bat`
3. `taskkill /F /IM explorer.exe`
4. `start explorer.exe`
5. Right-click in any File Explorer window.

### Known limitations / gaps

- No CLSID registration / unregistration tooling beyond the single `regsvr32` flow. If something gets corrupted in the registry, manual cleanup via `reg delete` is required.
- The `CoCreateInstance` hook fires on every COM activation in explorer once the DLL is loaded, not just modern-menu-related ones. Hot-path overhead is one CLSID compare against a 1-element array — small but measurable in tight loops.
- No `IExplorerCommand` registration. On Windows 11 24H2, the modern menu uses `IExplorerCommand` (sparse-package handlers) and may not enumerate legacy `IContextMenu` handlers at all. Without ExplorerPatcher (or `Shift+right-click`), the legacy menu — and our hook — may never fire.
- Icons are 28×28 only — no DPI-variant sources. Looks soft on 200%+ scaling.
- Per-paint allocations in `paint_layered` (DIB, GDI+ Bitmap, D2D RT, WIC bitmap) — fine for popup lifetimes, would matter if rendering becomes a hot path.

## What This Project Is NOT

- **Not a web service.** Single Windows DLL + auxiliary exes.
- **Not a general menu library.** Tightly coupled to right-click / context-menu semantics; uses inline hook on `user32!TrackPopupMenuEx` as its entry point.
- **Not production-ready.** No code signing, no automated tests, no CI. Distribution would require all three plus dealing with Win11 24H2's modern-menu enumeration not going through legacy `IContextMenu`.
- **Not multi-platform.** Windows 11 24H2 x64 only.
- **Not portable across DPI.** Currently `g_dpi_scale = 1.0` always; icons and corners look small on hi-DPI displays.
