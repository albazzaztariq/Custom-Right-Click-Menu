# Right-Click Menu API — Codebase Reference

## Project

Windows 11 24H2 in-process shell-extension DLL that **replaces** Explorer's right-click context menu. A consumer DLL describes the menu in a declarative macro tree; the host DLL inline-patches `user32!TrackPopupMenuEx`, extracts right-click context via shell COM, builds the menu by calling the consumer's `RegisterMenu()`, and renders an owner-drawn per-pixel-alpha layered window in place of the system menu. A separate subsystem registers `HKCR\.md → ObsidianMD` so double-clicking `.md` files runs `build/open_md_in_obsidian.bat`, which copies the file to a temp Obsidian vault, opens it via the `obsidian://` URL, and spawns `obs_watcher.exe` (event-driven via `SetWinEventHook`) to delete the temp file when the Obsidian window closes.

| Attribute | Value |
|---|---|
| Type | In-process Windows shell extension + `.md` double-click launcher |
| Runtime | Win11 24H2 x64 (verified Insider build 26200) |
| Language | C++17 (host + consumer + helper); batch + inline PowerShell (.md launcher) |
| Compiler | MSVC v143 |
| Build | `build.bat` (cl.exe direct); incomplete CMakeLists exists, unused |

## Architectural Principles (Do Not Violate)

1. **The host process never crashes because of us.** Every shell boundary is SEH-wrapped. Faults degrade to no-menu / fall-back-to-original.
2. **Inline hook is the actual interception.** 12-byte `mov rax, imm64; jmp rax` patch at `user32!TrackPopupMenuEx`'s function entry. IAT hooks remain as defense-in-depth.
3. **Per-tab `IShellBrowser` matching** — walk up from click HWND to active `ShellTabWindowClass`, match browsers by `IShellView` HWND descendancy. `IShellBrowser::GetWindow()` returns the cabinet HWND for ALL tabs on Win11 24H2, so naïve matching grabs the wrong tab.
4. **Menu tree built via thread-local pointer.** `_menu_internal::currentMenu` + `Submenu`'s `operator+` push/pop makes the nested `{ ... }` macro syntax produce a correct tree.
5. **Three-mode export attribute.** `MENU_API_DECL` switches between static link / dllexport / dllimport. Without it the consumer can't share state with the host.
6. **One window per menu level, each modal.** Cascading submenus recurse `show_impl`.
7. **Per-pixel-alpha layered window.** `WS_EX_LAYERED` + `UpdateLayeredWindow(ULW_ALPHA)`. No `DwmSetWindowAttribute`. No `CS_DROPSHADOW`.
8. **Silhouette + border share GDI+ path geometry** so anti-aliasing aligns.
9. **Text via D2D + DirectWrite into a private WIC bitmap** composited back source-over to the layered DIB — avoids premultiplied-alpha chiseling.
10. **Click-through dismissal.** 25 ms poll timer → `DestroyWindow` + synthetic `SendInput` re-injection at the cursor.
11. **Variable row heights.** Edge separator rows 16 px (`kEdgeSepHeight`), all others 40 px (`kItemHeight`). Painting, hit-test, total-height, and submenu Y all use cumulative `row_top_at` / `row_height_at`.
12. **URL parameters for `obsidian://` MUST be percent-encoded.** `examples/menu.cpp::UrlEncode` is the C++ reference; `build/open_md_in_obsidian.bat` mirrors it via `[uri]::EscapeDataString`.

## Data Shapes

The whole API surface is in `src/menu_api.h`. Canonical types:

```cpp
enum class ClickTarget {
    Unknown, File, Folder, Drive, DirectoryBackground,
    MultiSelection, VirtualItem
};

enum class Modifier { None, Shift, Ctrl, Alt, Win };
enum class ViewMode { LargeIcons, MediumIcons, List, Details, Tiles, Content };
enum class SortKey  { Name, DateModified, Size, Type, /* ... */ };
enum class GroupKey { None, Name, DateModified, Size, Type, /* ... */ };

// Context globals visible to RegisterMenu() (exported via MENU_API_DECL):
extern ClickTarget         target;
extern std::wstring        path;          // single-target convenience
extern std::vector<std::wstring> paths;   // multi-selection
extern std::wstring        parentFolder;
extern std::wstring        extension;
extern std::vector<std::wstring> extensions;
extern int                 selectionCount;
extern int                 modifiers;     // bitmask of Modifier
extern POINT               clickLocation;

// Tree node (internal — consumer interacts only through macros):
struct MenuNode {
    std::wstring text, shortcut, iconPath;
    int handlerId;          // -1 for submenus / separators
    bool isSeparator;
    std::vector<MenuNode> children;
};
```

Consumer API macros (`Selection`, `Submenu`, `Separator`) expand to `_menu_internal::*_helper(...) + [&]() { body }`. The trailing semicolon is the only C++ tax the consumer pays.

## Error Handling

- **SEH** wraps every shell boundary: `DllMain`, both TPM detours, `build_menu_for_current_click`, `dispatch_handler`. Consumer faults degrade to no-menu / fall-back, never to an explorer crash.
- **C++ exceptions** are caught at the same boundaries. The host never lets one cross back into Win32 code.
- **COM `HRESULT`** is checked at every call in `shell_context.cpp` / `folder_view_actions.cpp` / `examples/menu.cpp`. Failures log via `diag::log` and short-circuit.
- **No menu defined for context** → root menu empty → `with_inline_hook_lifted` calls original `TrackPopupMenuEx` so the system menu still shows.
- **Shift+RightClick** bypasses the hook entirely (lifts the patch, calls original, repatches). Manual escape hatch.

## Dispatch / Control Flow

```
right-click → explorer CoCreate our CLSID → DllMain runs (hooks installed)
            → explorer builds legacy popup → user32!TPMEx hits inline patch
            → TrackPopupMenuEx_detour:
                  populate_shell_context (per-tab IShellBrowser + selection)
                  build_menu_for_current_click (consumer RegisterMenu)
                  menu_window::show (paint + modal loop + outside-click)
                  dispatch_handler (consumer lambda under SEH)
```

For the `.md` Obsidian flow, two paths exist:
- **Right-click "Open in Obsidian"**: `examples/menu.cpp::OpenInObsidianFlow` — `CopyFileW` → `ShellExecuteA(obsidian://...)` → spawn `obs_watcher.exe`. Working.
- **Double-click `.md`**: `HKCR\.md → ObsidianMD → open_md_in_obsidian.bat` → `copy` → PowerShell `Start-Process obsidian://...` → spawn `obs_watcher.exe`. **Currently opens the vault but shows blank "New tab" — file lookup misses.**

Both paths use the same `obsidian://open?vault=X&file=Y` URL with percent-encoded components.

## Recipes

### Add a new top-level menu entry for files

1. Open `examples/menu.cpp`.
2. Inside the `if (target == ClickTarget::File)` branch (above `CommonFileOps()`), add:
   ```cpp
   Selection(L"My Action", L"Ctrl+Shift+M", L"my_action.png") {
       // your code; context globals path/paths/parentFolder are populated
   };
   ```
3. Place the icon at `assets/icons/my_action.png` (56×56 transparent PNG).
4. `build.bat`, `taskkill /F /IM explorer.exe`, `start explorer.exe`. Right-click a file to test.

### Add a per-extension override (like the existing `.md`)

1. In `examples/menu.cpp`, inside the File branch:
   ```cpp
   if (extension_exists({L".myext"})) {
       Selection(L"...", ...) { /* your action */ };
       CommonFileOps();
       return;
   }
   ```
2. Build and test.

### Add a submenu

```cpp
Submenu(L"More", L"more.png") {
    Selection(L"Thing A", L"", L"a.png") { ... };
    Selection(L"Thing B", L"", L"b.png") { ... };
};
```

### Add a folder-view action (View / Sort by / Group by)

1. Add the enum value to `SortKey` (or relevant enum) in `menu_api.h`.
2. Map it to a `PROPERTYKEY` in `folder_view_actions.cpp::sort_propkey_for` (or the equivalent).
3. Reference it from your consumer.
4. Build and test in a DirectoryBackground right-click.

### Add a refused CLSID for modern-menu suppression

1. Open `src/detours_hook.cpp` and append the CLSID GUID to `kRefusedClsids[]`.
2. To discover the right CLSID: set `kLogEveryCci = true`, build, reproduce a right-click, inspect `build/shell_extension.log` for `CoCreateInstance: clsid=...` lines, set the flag back to false, rebuild.

### Run a command as Admin from a menu action

Use `ShellExecuteEx` with `lpVerb = L"runas"` and `nShow = SW_SHOWNORMAL`. See `OpenTerminalAtAsAdmin` in `examples/menu.cpp`.

### Run PowerShell with safely quoted arguments

Use `RunPowerShellEncoded` in `examples/menu.cpp` — builds a Base64 UTF-16LE `-EncodedCommand` payload. See `CompressMultipleToZip` for an example consumer.

### Re-register the `.md` double-click handler

```cmd
reg add "HKCR\.md" /ve /d "ObsidianMD" /f
reg add "HKCR\ObsidianMD\shell\open\command" /ve /d "\"<full path>\WORKING\build\open_md_in_obsidian.bat\" \"%%1\"" /f
```

Replace `<full path>` with the absolute path to the project.

### Known limitations / gaps

- **Open in New Tab** uses a "last matching cabinet HWND in IShellWindows" heuristic. Brittle if Win11 24H2 changes IShellWindows ordering.
- **Pin to Start** removed from the menu. No in-process path exists on Win11 24H2 build 26200 to write to Start's Pinned grid — `IPinnedList3` returns `E_NOINTERFACE`, `start2.bin` is fully encrypted.
- **`obs_watcher.obj` at the project root** is a stray artifact from a manual compile. Either delete or move to `build/obj/`.
- **`CMakeLists.txt`** is incomplete; either complete to match `build.bat` or delete.
- **No `.gitignore`** — `build/` outputs (DLL/EXE/LIB/EXP/OBJ/LOG), `obs_watcher.obj`, log files are not excluded.
- **No code signing.** `shell_extension.dll` is unsigned; SmartScreen / WDAC may silently block registration on a stock machine.
- **No automated tests, no CI.** Only two interactive `.exe`s.
- **`.md` registry change is global.** `HKCR\.md → ObsidianMD` affects ALL `.md` double-clicks on the machine, not just from File Explorer.
