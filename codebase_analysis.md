# Right-Click Menu API — Codebase Analysis

## 1. Project Overview

Windows 11 in-process shell extension DLL that **replaces** (not extends) File Explorer's right-click context menu with a custom owner-drawn popup defined by a consumer-supplied DLL. The consumer writes a `menu.cpp` file that builds a tree of `Selection` and `Submenu` entries via two macros; the host DLL hooks `user32!TrackPopupMenuEx` (and related entry points) and renders its own per-pixel-alpha layered window in place of the system menu.

| Attribute | Value |
|-----------|-------|
| Type | In-process shell-extension DLL + sample consumer DLL + two test exes |
| Runtime | Windows 11 24H2 x64 (Build 26200), DPI-aware host (explorer.exe) |
| Language | C++17 (compiled with MSVC v143 / `cl.exe /std:c++17`) |
| Build | `build.bat` (cl.exe direct); `CMakeLists.txt` is a partial alt for test_harness only |
| Entry points | `DllMain` in `src/main.cpp`; `main()` in `test_harness/test_harness.cpp` and `hook_test/hook_test.cpp` |
| Output | `build/shell_extension.dll`, `build/menu.dll`, `build/test_harness.exe`, `build/hook_test.exe` |
| Libraries | `user32`, `gdi32`, `psapi`, `dwmapi`, `ole32`, `oleaut32`, `shell32`, `shlwapi`, `advapi32`, `windowscodecs`, `msimg32`, `gdiplus`, `d2d1`, `dwrite` |
| Test surface | `test_harness.exe` (no hook), `hook_test.exe` (hook pipeline), live explorer integration via `register.bat` |
| Custom font | Exo 2 variable font (`Font/Exo2-VariableFont_wght.ttf`), loaded at runtime via DirectWrite font set |
| Icons | 9 PNG icons in `assets/icons/`, generated from a ChatGPT mockup by `test_scripts/extract_icons.py`, rendered via GDI+ |

**Per-directory roles:**

- `src/` — the host DLL. All 19 files compile into `shell_extension.dll`. Architecturally split into: API surface (`menu_api`, `menu_node`), rendering (`menu_window`), shell integration (`hook`, `detours_hook`, `shell_context`, `class_factory`, `main`), state (`context`), utility (`diag`).
- `examples/` — single sample consumer file. Compiles to `menu.dll`, links against `shell_extension.lib` (the host's import library) so it shares the menu-tree state.
- `test_harness/` — Stage-1 test exe. Statically links the API (no DLL), calls `menu_window::show()` directly. Used for iterating on the API and rendering without any hook plumbing.
- `hook_test/` — Stage-2 test exe. `LoadLibrary`s the host DLL into its own process so the IAT/inline hooks install, then calls `TrackPopupMenuEx` directly. Proves the hook pipeline end-to-end without involving explorer.
- `Font/` — Exo 2 typeface. Only `Exo2-VariableFont_wght.ttf` is copied to `build/Font/` and loaded at runtime; the variable axis lets DirectWrite pick any weight from 100 (Thin) to 900 (Black).
- `assets/icons/` — 28×28 PNGs with transparent background. Copied to `build/assets/icons/` by build.bat. Loaded once and cached as `Gdiplus::Bitmap` per path.
- `test_scripts/` — Python helpers for asset prep (icon extraction, font name table dump). Not invoked by build; manual maintenance.
- `build/` — generated. Robocopy mirrors `assets/` and `Font/` into it on every build.

## 4. API Surface

**N/A — no HTTP/RPC surface.** The "API" is two C++ macros (`Selection`, `Submenu`) + one (`Separator()`) consumed inside a single function `void RegisterMenu()` in the consumer's DLL. The consumer reads context globals (`target`, `path`, `paths`, `extension`, ...) at right-click time and builds a tree declaratively; the host calls back into clicked-item lambdas via the handler registry.

## 5. Architecture Deep Dive

### Architectural invariants (do not violate)

1. **Host process (explorer.exe) must never crash.** Every shell boundary (`DllMain` body, each detour, `build_menu_for_current_click`, every consumer-lambda dispatch) is wrapped in SEH `__try / __except`. Faults degrade to "no menu shown" or "fall back to original" — never propagate.
2. **Inline hook is the actual interception.** IAT hooking proved unreliable (some call sites bypass the IAT slot), so the 12-byte `mov rax, imm64; jmp rax` patch at `user32!TrackPopupMenuEx`'s function entry is what catches calls. IAT hooks remain installed as defense-in-depth (`hook.cpp`).
3. **Tree built via thread-local pointer.** `_menu_internal::currentMenu` is "where I'm adding to". `Submenu`'s `operator+` does push/pop. This is what makes the nested `{ ... }` macro syntax produce a correct tree.
4. **Three-mode export attribute.** `MENU_API_DECL` at `menu_api.h` distinguishes `MENU_API_STATIC` (test_harness, no exports), `MENU_API_BUILDING_DLL` (host, dllexport), `(neither)` (consumer, dllimport). Without this, `menu.dll` couldn't share `currentMenu` / `handlerRegistry` state with the host.
5. **One window per menu level, each modal.** `menu_window::show_impl` creates a new window per submenu; cascading is recursive. Parent's WndProc is on the stack while child runs — intentional simplicity, but it's why `WM_SETCURSOR` override + auto-dismiss-on-sibling logic are needed.
6. **Consumer never types `[&]` or `std::function`.** The `Selection(...) { body };` macros expand to `helper(...) + [&]{body}`; `operator+` captures the lambda. The only C++ tax is the trailing `;` after each closing `}`.
7. **Per-pixel-alpha layered window for smooth corners.** `WS_EX_LAYERED` + `UpdateLayeredWindow(ULW_ALPHA)` with a 32bpp BI_RGB top-down DIB. DWM rounded-corner attributes are NOT used — we'd get an unwanted rectangular non-client frame on top of our alpha mask. `CS_DROPSHADOW` is also NOT used — it draws a hard rectangular outline.
8. **Silhouette + border share GDI+ path geometry.** Both the kBg `FillPath` and the navy 1px `DrawPath` use the same rounded-rect path so the AA aligns; otherwise the corners look bolder than the straight edges.
9. **Text via D2D + DirectWrite into a separate WIC bitmap.** GDI+ text on a layered DIB renders chiseled because of premultiplied-alpha quirks. D2D into a private `IWICBitmap` then composited back via source-over avoids that. The variable font's `wght` axis is set per-text-run (label = 450, shortcut/chevron = 250).

### Data flow / per-click dispatch

```

   │
   ▼
explorer enumerates ContextMenuHandlers under HKCR\<asset>\shellex
   │  - finds {7C3F4C5E-9D2E-4F7A-B5C8-1A3D4E5F6A7B} = RightClickMenuAPI

   │                                │
   │                                ├─ menu_window::show(rootMenu, x, y, owner)
```

### Error handling

| Layer | Mechanism |
|-------|-----------|
| `DllMain` body | SEH `__try/__except` — init failure leaves DLL inert |
| `build_menu_for_current_click` | SEH — consumer faults swallowed, partial rootMenu kept |
| Each TPM detour | SEH — falls back to original or returns FALSE |
| Handler dispatch | SEH — consumer lambda faults swallowed |
| IAT/inline patch failure | Logged; function returns false; pipeline continues |
| Consumer DLL load failure | Tolerated — host stays alive, no menu shown |
| WIC/D2D/DirectWrite create failure | Logged; text/icon rendering skipped; menu still shows |

The single rule: **the host process never crashes because of us.**

```

```

### First run

Three test surfaces, in increasing scope:

```
build\test_harness.exe        Stage 1: API + window paint, no hook
build\hook_test.exe           Stage 2: hook pipeline, no explorer
register.bat (admin)          Stage 3: live in explorer.exe
```

For Stage 3:
1. Right-click `register.bat` → Run as administrator. Writes HKCR\CLSID + per-asset `ContextMenuHandlers` + HKLM Approved.
2. Restart `explorer.exe` (Task Manager → End task → Run new task → `explorer.exe`).
3. Right-click in File Explorer.

If you have ExplorerPatcher loaded, the legacy menu path is used and the hook fires as expected. On stock Win11 24H2 the modern menu may bypass our hook even with the `{86ca1aa0-...}` HKCU override applied — disable the modern menu via the `ep_` toggle or live with Shift+right-click for legacy.

To remove: `unregister.bat` (admin), then restart explorer.

### Troubleshooting

| Symptom | Check |
|---------|-------|
| `cl.exe not found` | Not inside the x64 Native Tools Command Prompt |
| `LNK1104: cannot open file 'build\shell_extension.dll'` | A `hook_test.exe` or explorer.exe is holding the DLL. Kill `hook_test.exe`, or restart explorer if registered |
| Menu doesn't show on right-click in explorer | Check `build/shell_extension.log` for `TrackPopupMenuEx_detour FIRED`. Absent → modern menu not falling through to legacy. Try `Shift+right-click`. |
| Menu shows but text is missing/chiseled | DirectWrite font collection failed — check log for `DWriteCreateFactory` and `DWrite font collection` lines |
| Menu position wrong on hi-DPI | `g_dpi_scale` calc — confirm `GetDpiForWindow(owner)` returned the right monitor DPI in the log |
| Border looks bolder at corners than edges | Pen alignment — must be `PenAlignmentCenter` with path inset by half-pen-width and corner radius reduced by same |

## 7. Technology Stack

| Area | Tech |
|------|------|
| Compiler | MSVC v143 (`cl.exe /std:c++17`) |
| GUI primitive | Win32 `WS_EX_LAYERED` popup + `UpdateLayeredWindow(ULW_ALPHA)` |
| Vector / shape rendering | GDI+ (`Gdiplus::Graphics::FromImage` on PARGB `Bitmap`) |
| Text rendering | Direct2D `ID2D1RenderTarget` on a private WIC bitmap, plus DirectWrite `IDWriteFactory5` + `IDWriteFontSetBuilder1` for variable-font axis support |
| Image decoding | WIC (`CLSID_WICImagingFactory`) — used by GDI+ `Bitmap::FromFile` for icon PNGs |
| Hooking | Hand-rolled IAT walker + 12-byte `mov rax; jmp rax` inline patch (no Detours dependency) |
| Shell COM | `IShellWindows`, `IShellBrowser`, `IShellView`, `IFolderView`, `IShellItemArray`, `IPersistFolder2` |
| Self-registration | `regsvr32` invoking our `DllRegisterServer` / `DllUnregisterServer` |
| Font | Exo 2 variable font (Google Fonts, OFL license) |
| Asset prep | Python 3 + Pillow + numpy |

## 9. Key Insights & Recommendations

### Strengths

- **Defense-in-depth on the host-stability invariant.** Every shell boundary is SEH-wrapped. Combined with the inline-hook fallback when IAT hooks miss, this is genuinely robust scaffolding for a shell extension.
- **Three-rendering-stack split is principled.** GDI+ for shapes (best AA), D2D+DirectWrite for text (best on layered DIBs, variable-font axis), GDI+ stroke for border (same geometry as silhouette so AA aligns). Each was chosen after debugging the previous approach.
- **Good incremental verifiability.** Stage 1 / Stage 2 test exes mean rendering and hook pipeline can be debugged without involving explorer at all.
- **Clean DPI strategy.** A single `g_dpi_scale` thread-local + `S(v)` / `Sf(v)` helpers means scaling is opt-in per usage rather than mixed in everywhere. Currently fixed at 1.0 (literal pixels in explorer at all DPIs) but the infra is in place to make it monitor-DPI-aware.
- **No external runtime dependencies.** No vcpkg, no Detours, no Conan. Just MSVC + Win32/COM/GDI+/D2D — everything in the SDK.

### Gaps and concrete improvements

- **`detours_hook.cpp`'s `kRefusedClsids[]` is one placeholder.** No actual modern-menu CLSIDs are in the refusal list. With `kLogEveryCci = true` you can discover the real ones in situ; bake them in once known. (`detours_hook.cpp:34-39`)
- **No automated tests.** `test_harness.exe` and `hook_test.exe` are interactive — open a popup, expect a click. No assertions. A minimal headless smoke test would catch regressions in the rendering pipeline or shell-context extraction.
- **No CI configuration.** `.github/`, `.gitlab-ci.yml`, etc. all absent. Adding a Windows-runner GitHub Actions workflow that runs `build.bat` and verifies the four artifacts appear would catch broken-build commits.
- **CLSID is hard-coded.** `class_factory.cpp:9-12` and `class_factory.h` carry the same GUID literal twice. Acceptable but error-prone if the CLSID ever changes.
- **No icon size variants.** Icons are 28×28 PNGs only. On 200%+ DPI displays they'll either look soft (if scaled) or chunky (if rendered 1:1 at 28 physical pixels). Adding 56×56 / 84×84 sources and picking based on `g_dpi_scale` is the standard fix when DPI scaling is re-enabled.
- **No consumer error reporting.** If the consumer's `RegisterMenu()` faults, SEH swallows it silently (correctly, for host stability) — but there's no `diag::log` of the SEH catch in `main.cpp:107`. Adding one would help debug consumer bugs without crashing explorer.
- **Build artifacts checked into source tree.** `build/` contains `.obj`, `.exe`, `.dll`, `.lib`, `.exp`, `.log`. A `.gitignore` is missing. Recommend adding one.
- **`CMakeLists.txt` is incomplete.** Only builds `test_harness.exe`. Either complete it to match `build.bat` or remove it to avoid confusion.
- **`Rough Spec.md` is the design source of truth but isn't linked from `Quick Guide.md`.** Add a one-line cross-reference.

### Security considerations

- **No code signing.** `shell_extension.dll` is unsigned. On stock Win11 with SmartScreen enabled, registering an unsigned shell extension may be blocked silently in some Insider builds. Recommend signing (even self-signed + trusted root) for distribution.
- **`HKLM` writes from `DllRegisterServer`.** The Approved-handlers entry is written to HKLM. Already requires admin (regsvr32 elevates), so this is correct; just flagging that anyone who runs the unsigned regsvr32 trusts our DLL.
- **CoCreateInstance interception is invasive.** Our hook fires on EVERY `CoCreateInstance` in explorer once the DLL is loaded, not just modern-menu-related ones. The hot-path overhead is small (one CLSID compare against `kRefusedClsids`) but is still measurable. Consider gating with `kLogEveryCci` only enabled in debug builds.

### Performance

- **Per-paint allocations.** `paint_layered` allocates a fresh DIB, GDI+ Bitmap, D2D render target, and WIC bitmap on every paint (every WM_PAINT, every hover that changes highlight). For a popup that lives milliseconds this is fine, but if hover-flashing ever becomes an issue, caching the DIB across paints would help.
- **Icon decoding cached correctly.** `icon_for()` caches `Gdiplus::Bitmap*` per consumer-path string. Good.
- **Font collection rebuilt on first call.** `ensure_custom_font_loaded` is idempotent (`static bool loaded`). Good.

### Maintainability

- **`menu_window.cpp` at ~1100 lines is long but coherent.** Could split into `menu_render.cpp` (paint passes) + `menu_window.cpp` (window lifecycle + WndProc) if it grows further.
- **Icon path strings are bare `const char*`.** Changing an icon name requires touching `examples/menu.cpp` and the actual file in `assets/icons/`. A typed constants header (`icons::view`, `icons::copy`, ...) would catch typos at compile time.
- **The 9 documentation files (`README.md`, `Rough Spec.md`, `Docs/Quick Guide.md`, `Docs/Codebase File Tree.md`, `Docs/Deployment Status.md`, `codebase_analysis.md`) overlap.** Consider whether `Quick Guide.md` makes `README.md` redundant after this regen.
